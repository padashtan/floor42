# Floor42: progress notes

The resume point for coding agents and contributors. Read this first, then `docs/adr/` (index in `docs/adr/README.md`),
`docs/DEBT.md` and `CLAUDE.md`. Keep it short: what is true today, how to work, what to avoid. The history of each
change is in git and `CHANGELOG.md`; the reasons are in the decision records.

## State

- Version in the poms: 1.0.0. This content is the
  first public v1.0.0 (director's decision 2026-11-11; the scope is frozen: new ideas go to `docs/V2_IDEAS.md`). The
  public repository receives it as one single commit, without the private history, on the director's go.
- What it is: a daemon (Quarkus, Java 25) that runs Claude Code agents under governance enforced by code, an event
  sourced domain (`floor42-domain`), an append-only SQLite journal, and a Vue 3 + three.js office as the interface
  (`floor42-web`). Agents are Claude Code sessions, never direct model calls.
- Agent identity with Keycloak (IAM mode, opt-in, ADR-0064; `iam/README.md`), the token broker, the mandatory WSL
  sandbox for REAL missions with a journaled unsafe mode (ADR-0063), session risk detection (ADR-0066, detection and
  alerts only), the OIDC conformance run, the assurance chain (`docs/quality.md`, `docs/security-scanning.md`).
- Debt: `docs/DEBT.md` (at most 5 open items, `DebtGateTest`). Ideas and known flaky tests: `docs/V2_IDEAS.md`.
- Decision records written before 1.5.0 say "Office" (the former name); some cite `spike/*` branches, which are
  throwaway experiments that are not in this repository.

## How to resume

- Fast loop (CLAUDE.md): `bin/floor42-dev` for dev mode, `./mvnw -q -pl floor42-server -am test -Dspotless.check.skip=true -Dtest=<Class> -Dsurefire.failIfNoSpecifiedTests=false` for one class, `make test-fast` for every test without the web build. The full gate, `./mvnw -q spotless:apply; ./mvnw verify` (`make verify`), only before a merge to main and a release.
- Build and run: `cd floor42-web && npm ci && cd .. && ./mvnw verify`, with `JAVA_HOME` on a JDK 25 (or `FLOOR42_JAVA`). Stop a running daemon before `./mvnw package` (Windows locks the jar). `bin/floor42` (`bin\floor42.ps1` on Windows) copies the build to `~/.floor42/app`, keeps data in `~/.floor42`, serves the UI on http://127.0.0.1:7420 and asks the daemon to open a single-use sign-in link in the browser (ADR-0034). Scripts that need a bearer token use a script token from the desk (System > Sessions and tokens, ADR-0044; `FLOOR42_TOKEN` for `floor42 "objective"`).
- Tests: domain (JUnit, fast), server (`@QuarkusTest`, SQLite per run, fake Claude Code in `floor42-server/src/test/resources/fake-claude`), web (`npm test`, Vitest), browser journeys (`make e2e`, before a release). No test may call a paid model.
- Changing a view or a route: refresh the contract snapshot with `./mvnw verify -Dfloor42.openapi.write=true` (or the single `OpenApiContractTest`), then fix `floor42-web/src/api/types.ts` until `contract.ts` type-checks.
- The director writes improvement notes in Floor42 (desk, checklist): read them with `GET /api/notes` and apply the open ones.

## Decisions taken along the way (not all in ADRs)

- A tool call Claude Code refuses itself, before the hook (Haiku calling Bash in a review session that does not offer it, seen on M-7 T-21), is recorded from the stream as blocked upstream (`recordUnseenCall`); if it ever ran, it is an unauthorized execution and suspends the mission. A session the previous daemon left open is closed as `interrupted` at startup, and the director is asked "Retry".
### Behaviours worth knowing

- Never let an agent deploy Floor42: on M-10 an agent allowed to run Bash read `~/.floor42/session.token`, called the API as the director, copied its own unreviewed build into `~/.floor42/app` and stopped the daemon, which ended its own session. `ShellGuard` denies shell commands that name the data directory or stop the daemon (a text check); since ADR-0034 there is no director token at rest to read, and an agent's own credential gets 403 on the API. Deployments stay with the director.
- Committee seats of the director's own (event `CommitteeSeatDefined`, `POST /api/committee/roles`): the key and the member's id are the name made a slug; Floor42's seat names are refused; `CommitteeRoles.all(c)`, `select(keys, panel, c)` and `of(agent, c)` include them, the static `all()` and `of(agent)` stay built-in only (any member may be dismissed but the two chairs; a built-in seat whose member left stays listed `vacant` and is refused by `select` before any mission is created). Consultations (`CONSULT: <role>`) still offer built-in roles only.
- A folder without git: `POST /api/projects/init` (git init, first commit signed Floor42, files already there included); refused for a drive root, the home folder, the data directory, more than 5000 files.
- The director's files (`DirectorFiles`, `/api/missions/{id}/files`): the one place Floor42 writes to the director's checkout, on their click (a commit of the given paths, or of everything pending). `update-agents` merges the director's HEAD into each worktree that does not contain it, refused while any session of the mission runs; a clean merge moves the workspace's `baseCommit` to that commit, a conflict is undone by `Workspaces.merge`. On Windows git may give a file back with CRLF after `merge --abort`: compare contents, not bytes.
- Claude Code stream lines: `tool_progress` (a heartbeat every 30 s, `parent_tool_use_id` names the call) becomes `ActionProgressed` on an AUTHORIZED action. Any other unknown line carries its shape (keys and types) and its content masked by `StreamJsonParser.masked`; it is journaled (`RuntimeLineRecorded`) only for a kind in the setting `ACCEPTED_STREAM_LINES`, otherwise the desk shows it with an Accept button. Fake marker `[fake:progress]` emits a heartbeat and a `brand_new_line` after each allowed tool.
- Business analyst (WorkRole.ANALYST, Linnea, hired with the first committee): stages CLARIFICATION (its session; `worksOn` lets the committee's analyst open it) and AWAITING_ANSWERS (blocking CLARIFICATION questions). The last answer emits `CommitteeClarified`; `LiveMissions.react` must wake the dispatcher on it: the dispatcher only wakes on events it lists, which is how work silently stalls. Fake marker `[fake:clarify]`: members add a QUESTIONS line until "The director answered" is in their brief; the analyst plays `analyst.txt`.
- Sandbox readiness (ADR-0033): `SandboxProbe` runs one `wsl.exe` through `Sandbox.argv` in `<data>/sandbox/probe` (never the project); its process seam `ProbeRunner` and the OS name are swapped by `useForTests` (`SandboxApiTest`): no test starts wsl.exe. A tool is MISSING only from a complete probe line; no measure, a timeout or a cut line give UNKNOWN. `SHELL_SANDBOX` set to `wsl` forgets the last measure (`Company.sandboxTools` null). Recipes are copy-only: apt on Debian/Ubuntu, the nodejs.org tarball into /usr/local for a Node newer than the distribution's (majors in `InstallRecipes.DISTRO_NODE`).
- Context gauge (W18, 2026-10-31): `StreamJsonParser` turns the usage of each main-session `assistant` line into `ContextUsage` (input + cache writes + cache reads of the last request). Claude Code sends one line per content block, several sharing one `message.id` and the same usage: the last per message counts, never a sum (`ContextGauge` drops the repeat). Lines with a non-null `parent_tool_use_id` are a subagent's own context and are left out. `ContextWindows` holds the documented windows (Claude 5 family and 4.6+ at 1M, Haiku 4.5 at 200k); an unknown model, an alias like `sonnet` included, has `windowTokens` null and the UI shows "unknown window", never a percentage. In memory only (last 200 sessions), never journaled, so no `Origin`: `/ws/context` (pattern of `ApiCallStream`) and `GET /api/sessions/{id}/context` (the id the mission lists, `M-1:<session>`). Replays push nothing. Floor42 writes only the brief to a session's stdin, so it cannot ask `/context` and has no categories; the UI says so. UI: `state/context.ts`, `ui/contextGauge.ts`, profile gauge and crew-card bar.
- Stall alert (1.5.0): `LiveMissions.stall(m, now)` runs the dispatcher's own `nextTask` (now given the busy set as a parameter) with the agents busy and held as they are. STUCK only when it returns a task, the dispatcher holds none of the mission, and nothing of the mission happened since the last sign (an event of it, a task starting or ending, else the daemon's start) for `STALL_MINUTES` (default 5). Otherwise it names the wait, in this order: RESTING, a question holding the mission, COMMITTEE_DIRECTOR, AGENT_BUSY (the same rule with nobody busy finds a task; "elsewhere" from the dispatcher's reservation, else the agent's open session), HELD_PATCH (the same with nobody held), PROPOSED, any open question; else IDLE. Demo and ended missions are IDLE/NOT_DISPATCHED. The last sign and the reservations are in memory only. The UI reads it through one poller (`state/waits.ts`): the Progress panel, a red badge on its button, `(n)` in the tab title, notifications (opt-in, `tag` per item), and `OfficeScene.setStuck` for the "?" glyph. "While you were away" (`AwaySummary`, `GET /api/journal/summary?since=`) reads `Journal.since(seq, limit)` (primary-key seek, at most 20000 events, `more` past it); the acknowledged sequence lives in localStorage (`office.away.acknowledged`), never in the journal; a first visit only stores the head.
- Pull requests (ADR-0036): `PullRequests` (service), `PullRequestText` (the body, from the journal and git, no model), `GhCli` (seam; `GhCli.Process` runs `floor42.gh.command`). Director only: the domain's `checkPullRequest` refuses any other actor (`FORBIDDEN`, SYSTEM included) and simulated missions; `ShellGuard` refuses an agent's `git push` (git options before `push` allowed for; a commit message naming "push" is fine) and any `gh` call. The remote's configured URL is read with `git config --get remote.<r>.url` (never rewritten) and passed to gh as `--repo host/owner/name`. Before pushing Floor42 runs `gh pr list --head` (an open one is recorded as `found`, nothing pushed); after a failed push `git ls-remote`; after a failed or timed-out `gh pr create` the lookup again: FOUND, FAILED (retry safe) or UNKNOWN (no retry offered). The UI offers workspaces' branches only; the API also takes the project's current branch (no `workspace`).
- Replay export (ADR-0035): `ReplayExports` (api) reads the mission's events from the journal under the service lock, builds each line with `EventView.of`, and passes every text through `security/ReplaySanitizer` (token, known folders to `<repository>`/`<worktree:agent>`/`<floor42-data>`/`<home>`, other absolute paths to `<path>`, `SecretMasker`, clip 1500 for outputs / 2000 for texts). `SettingChanged` values and `DirectorEditedFile` diffs are never read into it. The POST needs the preview's `digest` (SHA-256 of the cleaned content), and `html()` refuses to return a file still holding the token. The player is plain script in `floor42-server/src/main/resources/replay/player.js` (no build step); its Vitest (`floor42-web/src/replayExport/player.test.ts`) loads that very file with `?raw`. Its labels come from the UI (`replayExport.file.*`). Fake marker `[fake:leak]`: a developer session plays `leak.txt` (secrets, Windows/POSIX/UNC paths, `{{lorem}}` expands to a long text).-
### Agents and governance

- Agents are Claude Code sessions, never direct model API calls (ADR-0006). Floor42 never touches Claude credentials.
- Agent sessions run with `--restricted` and HTTP hooks with `"onFailure": "block"` (fail closed).
- An action that errors without an Floor42 authorization is a block, not a failure; one that succeeds without authorization is a critical incident that suspends the mission.
- Agent status is derived from facts, never stored. "Suspend new assignments" does not stop work in progress.
- Approvals: "ask once" remembers the answer per agent and tool, per exact command for Bash (ADR-0010). A remembered approval is an answered approval question not marked by `ApprovalForgotten`; one-off questions (ask every time, a file the director edited) are marked at ask time.
- Replays never invent results: a call the recording was refused has "no result to replay".
- Context continuity: each session gets a brief built from the journal, never a long chat history (ADR-0011).
- File tools never leave the worktree, whatever the table says (ADR-0012); the shell is not confined (D5), so Bash stays ask-per-command.
- The workshop does file work through Floor42 (git in the worktree), confined like agents, then journals it (ADR-0013). Accepting commits on the agent branch; the director merges it.
- Checks are the director's command run by Floor42, never an agent's word. Budgets compare with Claude Code's estimates, checked between sessions only (ADR-0014).
- Committee contributions end with PROPOSAL / POSITION / CRITICAL OBJECTION; a standing critical objection is never outvoted; the director may still adopt despite it, and the decision records that (ADR-0015).
- Plan usage (ADR-0016): `rate_limit_event` readings are journaled as `PlanUsageObserved` (measured). Before every session, after the budget, Floor42 holds a step a window would likely cut and asks: wait for the reset, run anyway, stop.
- Ticket-by-ticket validation (ADR-0017): with "let Geoffrey plan", Geoffrey's read-only session proposes tickets; in a mission with `TicketValidationEnabled`, any ticket not created by the director starts PROPOSED.
- Review help (ADR-0018): a reviewer ends with `CONSULT: <role>: <question>` or `RESEARCH: <question>`, once per review round.
- Hiring and parallel work (ADR-0019): hirable roles DEVELOPER, REVIEWER, RESEARCHER (PLANNER is a work role too, held by Geoffrey only, and cannot be hired); `LiveMissions.produce` is a dispatcher, up to `floor42.parallel.max-sessions` (default 2) sessions per mission; each developer carries one ticket at a time in its own worktree; reviews by a free reviewer who did not produce the ticket; a ready ticket goes to the developer of its dependencies; a ticket with an open question waits. Dismissal is refused only while the agent is at work (an open session, or a task reserved by the dispatcher); a ticket it had started goes back to the queue (`TicketReleased`), a delivery in review stays there, and if that review rejects it the dispatcher releases it too (`LiveMissions.releaseLeftBehind`).
- Dispatcher rules settled by the 2026-10-21 review: one dispatch lock for all missions, so an agent is chosen and reserved atomically and never runs two sessions; a task reserves every agent whose session it runs (committee members, the consultant or researcher); a failed production, planning or committee session, or an unexpected error, asks the director with "Retry", so the mission waits instead of looping (a failed review is recorded UNVERIFIABLE, which escalates; a failed consultation or research is concluded without it by Floor42; a step the domain refuses is only logged); any answer to an escalated review starts the dispatcher again (M-7 stood still after T-19 until this was fixed); "Run anyway" covers the mission for 5 minutes; while resting until a reset nothing starts; a ticket answered "Leave it" stays put until a session runs on it. A consulted colleague is denied writing, the shell and the network for the consultation only (rules added, then removed). Hired researchers answer research requests; Hedy is hired on first need only. New missions go to the first active developer and reviewers, never to someone who left; only the two chairs, Geoffrey and Lucie, cannot be dismissed (2026-10-31; before, every built-in committee member was refused, Chris included since his id is the developer seat's); the ids of Floor42's own agents are reserved when hiring. When a task ends, every other mission in progress looks again (an agent it waited for may be free). The director resumes a mission suspended after an incident from the desk (`POST /api/missions/{id}/resume`).
- One ticket, one clean state (ADR-0019, 2026-10-22): agents do not commit, so a developer's worktree holds its finished ticket's changes until the director accepts (commit) or rejects (archive) them in the workshop. Until then that developer takes no new ticket (`LiveMissions.held`, measured with git, shown on the board, `GET /api/missions/{id}/held`); without this rule the next review read both tickets and a rejection undid both. A ready ticket whose dependencies were done by several developers, or by one no longer on staff, waits for a non-blocking question: "Go on without it" (its brief lists what is missing) or "Drop the ticket".
- Checks are evidence for one delivery only (2026-10-22, seen on M-8): a run is dated against the producer's last session on the ticket. A run before it is not shown as evidence; the reviewer's brief says the checks have not run on this delivery. The worktree's HEAD cannot tell, since agents do not commit.
- A developer at work (a ticket in progress or in review) is never reported as held: the changes in its worktree belong to the ticket under way (seen on M-8).
- Protocol drift (2026-10-22): the stream parser no longer ignores what it does not know. Known: `system/init`, `system/thinking_tokens`, `system/task_started` and `system/task_notification` (a background shell command), assistant `text`, `tool_use`, `thinking`, user `tool_result`, `result`, `rate_limit_event`. Anything else is `Unfamiliar`: noted on the session, logged once, listed by `/api/status`. A new Claude Code version is checked by recording a session into `floor42-server/src/test/resources/transcripts/` (redacted: user name, personal skills and commands) and adding it to `StreamJsonParserTest`.
- The packaged daemon serves the UI with `public, immutable, max-age=86400` on every file: the page itself is set `no-cache` by `PageCache` when its headers go out. A browser that loaded the page before that fix keeps the old one up to a day: Ctrl+F5 once.
- The scene's jokes are decoration: a fixed list in `scene/jokes.ts`, shown only for agents whose status sends them to the lounge, in their own bubble (`q.joke`), never in the activity line, which carries only the journal's words. The ping-pong rally follows the same rule: two idle agents at the table, nothing else.
- Session watchdog: `floor42.claude.session-timeout-seconds` (1800) is a silence limit, not a length limit. A session with no line on its stream and no tool call for that long, and no hook waiting for the director, is stopped with every process it started; before, the limit only applied once the stream had closed, so a stuck session held its agent for ever. Each running session leaves `process.txt` (pid and start time) in its folder; the next daemon stops what a dead one left running, only when the start time still matches.
- Staffing review (ADR-0022): the board's "Reinforce?" asks Geoffrey (light model, no tool, facts from the journal) on his own ticket, which the dispatcher never takes; her advice closes it, and when she names developers a non-blocking `STAFFING` question asks the director yes or no; only a yes hires them and raises `PARALLEL_SESSIONS` to her value.
- Retrospective (ADR-0020): when a real mission ends (completed or cancelled), the agents with a session on it speak once each from a facts sheet Floor42 composed from the journal (`WENT WELL:` / `WENT BADLY:`), then the chair (planner, else first reviewer, else first participant) concludes with `CONCLUSION:` and at most 5 `LESSON: <role|all>:` lines. Sessions run on `floor42.retro.model` (haiku), with no tool, on the retrospective's own ticket (the one session allowed on an ended mission). A turn the usage window would cut waits for the reset (the meeting room says until when, `GET /api/missions/{id}/retro/wait`, and the director may close it now, `closeRetroNow`: the turns due are recorded as not heard); a spent budget closes it unheard. Lessons bind nobody until the director accepts them (desk, Lessons tab); accepted lessons reach the developer, reviewer and planner briefs for their role (latest 8); the chair sees those in force and does not repeat them.
- Nothing that waits for the director lives in memory (D9): `LiveMissions` reads open questions to know a mission waits, and answers to know it resumes; `recover()` at startup, for real missions in progress that do not wait, honours the last resuming answer ("Retry", a raised budget, anything but "Stop" on a plan limit) to a question asked since the last session, and closes as interrupted any session left open. In memory only: the one-shot "run anyway", the rest until a reset (`resting`, rebuilt by `recover()`), and the tasks and agents running now (`running`, `busy`).
- Worktree branches: if `floor42/<mission>-<agent>` already exists, Floor42 takes `-2`, `-3`… and never reuses an existing branch, not even one it created; an existing worktree directory is reused as is.
- The director's improvement checklist is company-wide and journaled (`NoteAdded`, `NoteChecked`, `NoteRemoved`); note ids are never reused. A note becomes a ticket of a real mission in progress (note N-2, `POST /api/notes/{id}/ticket`, `NoteTurnedIntoTicket`): the director wrote it, so it is TODO at once and the dispatcher takes it; Once that ticket is done, Floor42 closes the note into the archive, with the commit the director accepted for it in the workshop (`commitFor`: the latest accepted on its developer's workspace since the ticket started), added later if it comes after. The director closes any note, naming the commit of work done elsewhere (`POST /api/notes/{id}/close`, `NoteCommitted`). The archive lists closed notes with ticket, commit and date.
- Time at work counts session lengths measured by Floor42, except interrupted sessions (`AgentSession.workTime()`): their recorded end is the next startup, not the end of any work (seen on M-7 T-21: 52 minutes of a dead session).
### Session risk v1 (ADR-0066)

- Detection and alerts only: a score per session from signals Floor42 already sees, `SessionRiskRaised` journaled at a strict threshold, a To do row proposing a quarantine the director applies by click (revoke, suspend, stop). No step-up, nothing automatic.
- Open question: in IAM mode no route re-delegates a suspended mission whose plan is already approved. Pending with the director; the plan recommends shipping v1.0.0 as is. Not measured yet: the cost on the allow path, the false-positive rate.
- Reason codes: POLICY_DENIED, COMMAND_DENIED, OUTSIDE_WORKSPACE, BROKER_PATH_NOT_ALLOWED, BROKER_METHOD_NOT_ALLOWED, BROKER_RESOURCE_NOT_GRANTED, BROKER_RESOURCE_UNKNOWN, INJECTION_MARKER, UNTRUSTED_READ, OWN_LEASH, plus derived BURST and TAINTED_THEN_REFUSED.
### Agent identity (v1.0.0, ADR-0064)

- IAM mode is opt-in (Settings, IAM section; a daemon restart turns it on). Off, nothing changes and no Keycloak is needed. Simulated sessions use a local fake issuer (`urn:floor42:simulated`), never accepted for a REAL session.
- Delegation is per mission: a Keycloak step-up re-authentication at each plan approval gives one offline session per mission. Measured: offline tokens of one SSO session share one offline session, so revoking one kills the others. The token broker and the agents' session tokens come from that offline token.
- The session token carries `floor42.{launch,mission,ticket}`, not Floor42's session id in `sid`, because Keycloak sets `sid` itself. Keycloak V2 emits no `act`: the mapper SPI in `iam/keycloak-extensions/` writes it. The requester must be in the subject token's `aud`. A mapper keeps the long lifespan only on a token whose audience is exactly `floor42-api` (the mapper cap rule).
- Introspection works only as a client in the token's `aud`: the 60 s check introspects as `floor42-api`.
- Process binding uses the in-memory PID from `builder.start()`, never `process.txt`. Break-glass: the console link still signs the director in but mints no delegation.
- Committee and auto-approved missions are blocked in IAM mode until a Keycloak approval. Broker catalogue and grants are files, edited through the API; the screen has no editor for them.
### API and cockpit

- The API documents itself (OpenAPI at `/q/openapi`, Swagger UI at `/q/swagger-ui`), loopback only.
- One resource per area under `@Path("/api")` (`AgentsResource`, `MissionsResource`, `TicketsResource`, `QuestionsResource`, `PermissionsResource`, `CommitteeResource`, `RetrosResource`, `EventLogResource`, `UsageResource`, `ApiConsoleResource`, `DemoResource`; `CompanyResource` is gone), constructor injection; shared id parsing and the director's command context are in `DirectorRequests`. Views live in one file per family (`AgentViews`, `MissionViews`, `TicketViews`, `ActionViews`, `QuestionViews`, `CommitteeViews`, `RetroViews`, `PermissionViews`, `UsageViews`, `JournalViews`, `Scorecard`); `Views` is gone. A schema is named after the record's simple name, so moving a record keeps the contract, but two records with the same simple name get `Name1` by scan order (`DirectorRequests.Reason` is `Reason`, `LessonsResource.Reason` is `Reason1`): check `OpenApiContractTest` after moving one.
- Errors: throw `RefusedException.invalid/conflict/tooLarge` (or a `DomainException`) and never build a `Problem` by hand; a new validation code of the domain goes into `ErrorMappers.VALIDATION` so it answers 400. Git runs only through `GitProcess.git`; read paths with `-z`, put `--end-of-options` before any revision that comes from outside.
- The API console (C) shows live every call to the API, the hooks, the WebSockets, login and `/q/openapi` (not the UI's static files nor Swagger UI); kept in memory (last 500), never in the journal; a token in a query string is masked. Clicking a call shows its request and response bodies (note N-1): JAX-RS interceptors (`ApiBodies`) copy them beside the call, up to 32 KB each, fetched on demand (`GET /api/calls/{sequence}`); the console's own history is not copied into itself.
- The director's daemon runs from a copy of the build (`~/.floor42/app`), so rebuilding never fights a running daemon.
- The page (`/`, `/index.html`) is served `Cache-Control: no-cache`: after a redeploy the browser loads the new bundle. The director's token and the browser sessions live in memory, so after each start an open tab must sign in again (its button asks for a link) (a stale tab retries `/ws/events` with 401s, harmless).
### The office on screen

- Rule: every animation is explained by a journal fact; nothing estimated is shown as measured (labels say "estimated", "measured by Claude Code", "general, not measured").
- Rooms: director's floor (1), compute room (2), open space (3) with ten desks, one per agent for good (an eleventh agent and later ones stand along the south edge). Agents come and go by the glass elevator only (the west door, which opened onto the void, is gone). An agent is in the office only with work the server records (`presentInOffice`: not AVAILABLE, not PAUSED); otherwise it takes the elevator down and comes back up when work is given to it; dismissed agents leave for good. Consequence: the lounge, the ping-pong rally and the jokes, which were for idle agents, are now rarely seen.
- Body language (`scene/life.ts`, tested): emblems above heads by shape and colour (cyan badge working, amber speech bubble waiting for the director, red triangle for a refused or failed action, grey pebble idle); full-speed typing, or a sheet held up for a READ tool, only while the status is EXECUTING; a celebration with confetti for the assignee of a `TicketCompleted` (assignee from the board's tickets); a hand to the forehead and a grey puff on `ActionDenied`; confetti at the board on `MissionPlanApproved` and `MissionCompleted`. Ambient only: breathing, looking around, a stretch every 15 to 30 s. The light warms in the evening from the local clock (scenery, like the city's windows). The board shows ticket counts per column. Focus glides the camera; hover shows a faint ring; the selection ring pops. `prefers-reduced-motion` turns off ambient motion, gestures, particles and glides. No sound yet.
- Quota gauges (1.6.0): next to the brand, never inside the rooms' scrolling strip (that strip overflows at 1920 px and hid them). `ui/quota.ts` decides current or `unknown since <reset>` on the page clock (ticks every 30 s), so a window that resets while the page is idle turns unknown on time. Claude Code reports the windows only during an agent session: with none, the bar says so.
- Walking (`scene/nav.ts`, `layout.ts`): A* on a 0.25 grid with 0.35 clearance around `WALLS` and `FURNITURE` (every floor prop, chairs and plants included). `layout.test.ts` builds the office with a stub canvas and fails when a mesh standing on the floor lies outside every footprint: give each new prop one. Crossing furniture is allowed only within 0.8 of an end that itself stands on furniture (sitting down, getting up). Props placed later go through `OfficeScene.placeProp` (moved if they would cut a station or the landing off; walking agents reroute).
- Sky traffic (`scene/sky.ts`, rules in `scene/skyPaths.ts`, tested): airliners, a helicopter with a spinning rotor, an airship with a scrolling light board, drones in the 2020s theme only. Scenery, like the city; nothing to do with the journal. Each crossing is a straight line just behind the tower (at least `BEHIND_MIN` = 18 along the line of sight, the office's far corner is at ~13) and above `SKY_FLOOR` = 3 (every neighbour, antennas included, stays under y = -2); the camera is orthographic, so distance does not shrink a craft, it only blurs it (depth of field from ~62): the lanes sit close and high, which puts them on screen above the far walls once zoomed out. At most 4 at once (1 when the measured frame rate is under 30), one take-off per frame at most, own clock from the clamped `dt` (a hidden tab adds nothing); `prefers-reduced-motion` empties the sky. ### Panel layout and the way out of every action (feat/ux-pass)

- Rule in `floor42-web/src/ui/panelLayout.ts`: one main panel at a time. `App.vue` watches the shown panels of the table (`panelMounts.ts`); the one that appears closes the others (`superseded`). Docked (`DOCKED`: log, selection, away) and overlays are outside the rule. A new panel in the table is main by default: add it to `DOCKED` only if it must always show. Escape order is unchanged (`closeOnEscape`, then `closeLastPanel`).
- Drafts of forms live in `state/drafts.ts` (not in the panels): add any new form's fields there and its panel id to `DRAFT_HOLDERS`, so automatic openings (mission end) offer a toast instead of replacing it. Child panels are declared in `PARENTS` (`panelLayout.ts`); `ui/onePanel.ts` wires the rule in `App.vue`.
- Terminal: a panel replaced by another only detaches its screen (the PTY keeps running, already so before this pass; test added). `DirectorTerminals` remembers which session opened each shell (`LocalAccessGuard.sessionOf`, none for the director's own token): signing one browser out closes only the shells that session opened (`closeOpenedBy`), another signed-in browser keeps its own; signing out everywhere closes them all (`closeAll`). A script token, even `all`, gets 403 `SCOPE` on both sign-out routes (`TerminalApiTest`). Drafts are emptied after a successful submit, a called meeting, a hire and an explicit sign-out; an expired session (a 401) keeps them, to send again once signed in. A draft is only what differs from a blank form, and the blank mission form drops the default seats left vacant, as the form does on mount. The four forms are mounted in `drafts.component.test.ts`.
- Cancel audit (what the server allows): meeting close, mission abandon, retro close, restore cancel, terminal close, ticket drop, plugin preview cancel, resume are in the UI. No route exists to cancel a staffing review already asked (`POST /api/missions/{id}/staffing`), nor to stop a meeting call in flight; the button shows why it is disabled meanwhile.
- Not done: an undo for a dismissed agent, a progress bar on long loads, a "docks" mode (a replaced panel returns when the new one closes).

## Known gotchas (development environment)

- Docker in the sandbox (feat/docker-honest, 2026-11-03): the sandbox never reaches the Docker daemon (`/run` is a tmpfs there, `unshare -Urm` drops the docker group). The tools probe asks the daemon in the same run; the answer (`SandboxProbe.docker()`, a `DockerAccess.Measure`) stays in memory, never in `SandboxToolsProbed`: UNKNOWN after a restart until the next probe. A plan whose project needs Docker measures it then and gets `DockerQuestion` (phrase `dockerUnreachable`, `dockerMissing` or `dockerUnmeasured`; options "I do the step myself" and `WITHOUT_DOCKER`, never `GO_ON_WITHOUT`, which `Dependencies.wentOnWithout` reads for the dependency question only). The director's step names only the tickets that NEED docker, else it is the mission's (`EnvironmentBlocker.missionStep`, briefs only); a Docker blocker asks `environmentBlockedDocker`. Opening the sandbox to Docker is only proposed (ADR-0056). The folder browser's "New folder" is `NewFolder` (`POST /api/projects/folders`, codes `NEW_FOLDER_*`).
- Permission authors (fix/permissions-applied, 2026-11-03): a rule Floor42 writes goes through `MissionPermissions` or `Implementation` with `Actor.system()`; only the director's own clicks carry `Actor.director()`. The screen tells them apart by the journal's actor (`PermissionPolicy.author`), and `setToolPermission` replaces a tool's ticket lines only when the director calls it. A domain test that builds a table as Floor42 uses `f.system()`.
- Agent-reachable configuration (fix/agent-reachable-config, 2026-11-01): never let the daemon read, at start, a file the agents' uid can write. A start acts on no file of the data folder (the restore lives in memory only). `ConfigGuard` refuses `.env` and `config/` in the working directory and any change to `quarkus.datasource.*`: move the journal with `floor42.data-dir`, never the URL. A test that needs a file planted before Quarkus starts plants it in its `QuarkusTestProfile.getConfigOverrides()` (`PlantedRestoreMarkerTest`).
- Live missions (refactor/live-missions, 2026-11-01): `LiveMissions` is only the facade the rest of the daemon calls (create, nudge, stall, held, reserve/release). The work is in `app`: `Dispatcher` (produce loop, wakes) picks through `DispatchBoard` (chooses under `DispatchLock` with `TaskSelection`, the one rule the `StallDiagnosis` reuses) and runs through `TaskRunners`, one `TaskRunner` bean per `Work` (Produce, Plan, Review, Consult, Committee; `@All List<TaskRunner>`, a new kind is a new bean). Every session goes through `SessionGate` (holds, governor, "Retry" on no report). Lock order: `DispatchLock` first, then the `OfficeService` monitor, never the other way: event subscribers run under the office monitor, so `EventReactions` (event class to a list of reactions, in registration order, with a per-batch context) and `DirectorAnswers` only read and call `MissionScheduler.fork`, which always starts a new virtual thread (never the caller's), logs what escapes, and after `ShutdownEvent` starts nothing and gives running work 5 s, without interrupting it (a cut session would be journaled as failed; the next start records it as interrupted). No raw `Thread.ofVirtual()` in these classes: fork through the scheduler. Start-up and recovery: `LiveStartup`, `MissionRecovery`. Tests reach `MissionRecovery.recover()`, `StaffProvisioner.ensurePlanner()`, `MissionHolds.restUntil(...)` directly.
- IO adapters (refactor/io-adapters, 2026-11-01): run git through the injected `runtime.Git` only: `run` gives the exit code as data, `out`/`toFile` need success and throw a `GitFailure` (command, exit code, stderr; mapped once in `ErrorMappers` to 409 `GIT_FAILED`; catch it only to turn it into a refusal of your own, cause kept); a git that cannot start always throws. A path from the director or the screen goes through `Confinement.relative(root, path, Mode)` (a `ConfinedPath`; `.git` refused for reading too, `OutsideWorkspace` is 400 `OUTSIDE_WORKSPACE`); agents' file tools keep `Confinement.violation`. JSON: inject Quarkus's `ObjectMapper` (static helpers take it as a parameter); only `EventCodec` (the journal's format), `ApiDocs` (OpenAPI filter, outside CDI) and `EnglishLines` (static catalogue) keep their own. A `catch` either says `// Handled: <why>` or rethrows with the cause. `Deliverables` = `MissionBranches` + `GitReader` + `WorktreeScanner` + `BlobSource` + `DeliverablesZip` (views in `Delivered`); `Plugins` = `PluginFolders`, `MarketplaceStore`, `ManifestReader`, `PluginPlan`, `PluginCli` (views in `PluginViews`); `PullRequests` = `PullRequestDraft` (preview), `PullRequestGit`, `GhClient`; making a folder a repository is `ProjectInit`.
