# Progress: gotchas on the build, the tests and the fakes

Part of the progress notes: see [`../PROGRESS.md`](../PROGRESS.md). A branch adds or edits lines here; the State and Next step of PROGRESS.md change only at merge to main.

- Quinoa does not serve the UI in tests: `/` reaches RESTEasy and its 404. `ErrorMappers.web` answers JSON under `/api`, `/hooks` and `/q/` only and a small HTML page elsewhere (`StatusResourceTest` checks the page's `Cache-Control` on that HTML). Returning null from a `@ServerExceptionMapper` gives an empty response, not the default handling.
- The fake Claude must use unique tool-use ids per session (the real CLI does): action ids are mission + tool-use id.
- The fake Claude picks committee scripts from the brief's opening ("member of" / "chair of the architecture committee"); script text writes line breaks as `\n`.
- The fake Claude plays `planner.txt` when the brief says "asked to plan mission"; a first review with `[fake:consult]` or `[fake:research]` in the objective asks for help, answered by `consultant.txt` or `research.txt`.
- The briefs' fixed prose lives in `floor42-server/src/main/resources/briefs/*.txt` (`{{name}}` placeholders, `BriefTemplate` refuses a missing or unused one); the fake Claude's markers above are in those files. `BriefsCharacterisationTest` keeps every brief, report and pull request text byte for byte in `golden/briefs.txt`: a wording change is recorded again with `-Dfloor42.golden.record=true` and reviewed as a diff.
- The fake Claude plays `retro-member.txt` when the brief says "This is its" retrospective and `retro-chair.txt` for "chair of the retrospective"; `[fake:slow=N]` in a brief makes each session take N seconds, to watch the scene.
- Retrospectives are off in tests (`%test.floor42.retro.enabled=false`) except `RetroApiTest`, which turns them on with a test profile: elsewhere they would add sessions to the missions under test.
- The fake Claude reports a 5-hour window when the brief contains `[fake:usage=0.97]` (it resets 6 s later). A test that leaves a window at risk holds every later test's sessions: wait for the reset before ending.
- `@QuarkusTest` classes share one journal per Quarkus application (`target/test-data/${quarkus.uuid}`); a class with its own `@TestProfile` gets its own. Assertions on `/api/journal` must filter on their own mission.
- The fake Claude plays `staffing.txt` when the brief says "whether to reinforce the team"; a `text|` script line keeps everything after `text|`, `|` included.
- `[fake:prove]` (with `[fake:touch=<file>]`) makes a developer session write a `PROVE.md` with one step Floor42 can run (`echo proof-ok`) and one for the director (ADR-0058). Server tests replace the sandbox with `ProofShell.useForTests(runner, works)` and `restore()` after: without it `/proof` probes the real WSL on Windows. The acceptance's proof question is off in tests (`%test.floor42.proof.required=false`) except `ProofApiTest`, which turns it on with a test profile.
- `[fake:hang]` makes a session start a long child process, report its pid, then go silent; `[fake:touch=<file>]` makes a developer session (not a review) write that file in its worktree, so its ticket leaves a change.
- `[fake:needs-tools]` makes the planner propose two tickets, the second one with `NEEDS: headless Chrome, pdftotext, python3` (`planner-needs.txt`); with the sandbox on and a probe seam that measures them absent, `MissingTools` asks its one question (`MissingToolsApiTest`).
- The fakes are compiled once per test run, before any test, into `floor42-server/target/fakes/fake-claude.jar` and
  `fake-gh.jar` (`FakeTools`, a JUnit `LauncherSessionListener`; a jar newer than its source is kept), for release 21
  because the `java` on the PATH runs them (it may be older than 25). `java FakeClaude.java` cost 0.8 s of
  compilation per session (122 sessions per run); the jar starts in 0.08 s. Dev mode still runs the fake from its
  source (no test build needed). Edit a fake's `.java` and the next test run rebuilds its jar.
- Fake gh (`src/test/resources/fake-gh/FakeGh.java`, run as `java -cp target/fakes/fake-gh.jar FakeGh --fake-state <dir> <args>`): `scenario` in the state folder (`auth=yes|no`, `default=<branch>`, `create=ok|timeout|fail`), optional `checks.json`; it writes `prs.tsv`, `title.txt`, `body.md` and `calls.log`. `%test.floor42.gh.command` names a command that does not exist, so a test that forgets `PullRequests.useForTests` sees "gh missing", never GitHub. The test remote is a local bare repository: `url.<bare>.insteadOf https://github.com/acme/app.git` in the tests' global git config (`GIT_CONFIG_GLOBAL`, `src/test/resources/gitconfig-test`, see `PullRequestsApiTest`) keeps GitHub's URL configured while git pushes locally; the repository's own copy would be refused by `NetworkConfigGuard`.
- `[fake:context]` makes a session send, after init, two assistant lines of one message with the same usage (19 204 tokens of context) and a subagent's line with a usage of its own (left out by the gauge).
- `StallTest` (package `app`) runs with the dispatcher off (its own profile): each test builds the journal state by hand and reads `stall(m, now + N min)`, so no clock is waited for; `LiveMissions.restUntil` is its seam for a rest after a usage window. The committee cases (questions of the analyst, AWAITING_DIRECTOR) are asserted in `CommitteeApiTest` with the fake Claude Code.
- The fake Claude writes its arguments to `fake-args.txt` beside the session's `settings.json` (so a test sees `--resume <id> --fork-session`); `[fake:crash-unless-resumed]` makes a session exit 3 after init unless it was started with `--resume` (`ResumeApiTest`, which also writes the Claude Code transcript under `target/test-claude-home/projects/<slug>`).
- The terminal's fake (`src/test/resources/fake-tty/FakeTty.java`, `%test.floor42.terminal.command`) prints `FAKE-TTY ready tty=<bool> term=... floor42-env=[names] args=[...] cwd=...`, then answers each line: `/cost` prints a cost line, `child` starts a sleeping child (`ping -n 600` on Windows, `sleep 600` elsewhere) and prints its pid, `exit` ends with code 3, anything else is echoed. A Vert.x WebSocket client adds its own Origin unless `setAllowOriginHeader(false)`, which also drops one set by hand.
- A test that changes state with the browser's cookie must send `Origin: http://127.0.0.1:<port>` and `X-Floor42-Request: 1` (ADR-0044); with the director's bearer token it needs neither. A browser session for a test: `SessionRegistry.openBrowser("test").secret()`. `SessionsApiTest` has its own profile: signing out everywhere replaces the director's token.
- `[fake:forge=<file>]` (a path with forward slashes) makes a session report `forge: journalWritable=0|1 credentialsReadable=0|1 daemonStdout=0|1|na`: permission checks only (opening the journal for writing, the named planted file for reading, resolving `/proc/<parent>/fd/1`), never reading or writing content.
- `[fake:leak]` makes a developer session (not a review) play `leak.txt`: Read outputs holding secrets, Windows, UNC and POSIX paths, and `{{lorem}}`, which the fake expands to a text longer than any clip (`ReplayExportApiTest`).
- Dev mode (`bin/floor42-dev`, `%dev` in `application.properties`): port 7421, data `~/.floor42-dev`, sign-in link on
  stdout, the fake Claude Code from its source unless `--real-claude`, instrumentation reload. It must run with `-am`
  (the domain is never installed: `quarkus-maven-plugin` sits in the parent's pluginManagement so the prefix resolves
  in the domain module) and `-Dspotless.check.skip=true` (spotless checks at `process-sources` now). A shape change
  (new field or method) still restarts the app (about 10 s) and drops Vite's HMR socket, which the page reconnects.
  Stop it with `q` or Ctrl+C; a killed launcher leaves the dev JVM and Vite running (kill the tree).
- A real mission's plan needs its cap decided before approval (`CAP_NEEDED`): server tests approve with `{"noCap":true}` (or a `budgetUsd`), domain and runtime tests record `setBudget(director, m, null)` first. Keep that when you add a test that approves a real plan.
- `[fake:check-escape]` in a check's `does` plays `check-escape.txt` in that check's session only (its brief quotes the step's text): it tries `git push` and a write under `.github`, then validates.
- `[fake:rejected]` makes every review answer REJECTED (the ticket goes back, then to the director once rejected twice); `[fake:unverifiable]` makes a review answer UNVERIFIABLE; `[fake:env-blocked]` makes a developer's report end with a `BLOCKED BY ENVIRONMENT` line (a desktop browser); `[fake:unoffered]` makes every session call Bash as a tool its session does not offer (Claude Code refuses it itself, no hook runs). `DispatchRecoveryTest` plays a restart by calling `MissionRecovery.recover()` while a session runs; the fixture then waits for that session to end.
- Proving that nothing starts (test/hygiene, 2026-11-01): never sleep. `SchedulerQuiet.await(scheduler)` (test sources, package `app`) waits until `MissionScheduler` runs no task (a fork registers its task before returning, a task the ones it starts before ending; `awaitQuiet` is package-private), then assert; a loop that never ends fails there with the tasks still running. A task that rests until a plan reset is left out by name (`plan-limit-<mission>`). The dispatcher's tests extend `DispatchFixture` (quiet dispatcher and no usage window at risk before and after each test, helpers) and assert on their own mission, tickets and agents: a count over the shared journal is filtered by id first. `Staffing`, `Retrospectives`, `DemoScenario` and `PracticeScenario` start raw threads the scheduler does not see: wait for such a thread's observable end first (the staffing test watches, through `SchedulerQuiet.probe`, the `staff-*` forks its `hire-` thread makes last), or justify a short fixed wait for an absence in a comment (`LiveDemoTest`, `PracticeMissionTest`). Quiet alone proves nothing when nothing could have started: nudge the mission before it (`LiveMissions.nudge`) and keep a control that shows the same work does start once allowed. The plan-limit rest test is skipped, not passed, when the window resets before its count.
- Test map (ADR-0068, 2026-11-13): `tools/test-map.conf` says which tests a path calls for; `TestMap` (server test sources, JDK only) reads it and is run from its source (`java floor42-server/src/test/java/dev/floor42/server/TestMap.java select`, paths on the input) by `bin/floor42-quick` and by the gate scripts. First rule wins; a path with no rule runs everything. `TestMapGateTest` fails on a source file with no rule, a selection with no test class, an unknown journey tag, or a targeted share of the server under 60 percent. A new context needs only its `e2e-of` line.
- Escape survey: the gate scripts print `survey: N paths, java targeted|all|none, F failing, E escaped: ...` and append it to `~/floor42-escapes.tsv` (one ledger per machine, the Linux one in the WSL home). Read it before trusting the quick loop on a context; a real escape gets a rule.
- Quarkus boots: with several test JVMs each `@QuarkusTest` class boots its own daemon whatever its profile (Surefire sends one class per JUnit request, Quarkus stops the application at the end of a request): 106 boots in `verify`. A class orderer cannot change that. One JVM (`-Dfloor42.test.forks=1`): one request, classes grouped by profile. The gate prints `boots: N`. Measured 2026-11-16 (Windows, every Java test): 1 JVM 48 min 49 s, 15 boots, red on 9 classes that leak state into the reused daemon (list in ADR-0068); 2 JVMs 15 min 19 s, 106 boots, green; quick loop for one `app.delivery` file on 1 JVM 4 min 47 s, 3 boots. Fewer boots with several JVMs needs classes batched per request (suites per lot): not done, see ADR-0068.
- Browser tests (v1.2): `use.actionTimeout` is 20 s (`playwright.config.ts`), `FLOOR42_E2E_ACTION_TIMEOUT` (ms) overrides it. A vanished element now fails in 20 s, not at the test's 120 s. Count-then-act (`if (await x.count()) await x.click()`) races an element that leaves in between: give the action its own short `timeout` (inside `toPass` retries) or `.catch`.
