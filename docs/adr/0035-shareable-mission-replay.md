# ADR-0035: A mission exported as one self-contained replay file, cleaned by code

Status: Accepted, 2026-10-31 (1.5.0)

## Context
The director wants to show a mission to someone who has no Office: send one file, the other person opens it offline
and watches the mission play, every event with its origin (REAL / SIMULATED). The file leaves the director's machine,
so what it carries matters more than how it looks: the journal holds tool outputs, the director's objectives and
commands, absolute paths of the machine, and an agent's output may hold a secret it read.

Options weighed for the player:
- **The 3D office, inlined.** The scene is driven by the Vue app, which reads the API's current state (agents,
  tickets, layout, sessions) and the event stream. The journal holds events, not the API's answers at each instant
  (the online demo records those answers live, ADR-0031). Inlining it means a second build of the whole UI (three.js
  and the scene: 1,036 kB of minified script, measured on this branch's `vite build`) embedded in the daemon,
  an answer to every GET route rebuilt from events for every instant, and a file nobody can read before sharing it.
  Rejected: too costly to build and to audit.
- **A 2D plan in plain script.** One desk per agent (lit when its event is the current one, its screen lit when the
  event ran a tool), the board's columns rebuilt from ticket events, and the event log, with a timeline. About 15 KB of
  script and CSS (11.7 KB and 3.8 KB) a person can read in the file. Chosen.

## Decision
- **Only on the director's request.** `GET /api/missions/{id}/replay-export/preview` lists what the file will hold
  (events by origin, agents, tickets, clipped outputs, recorded costs) and everything masked or left out, by kind and
  where; it builds no file. `POST /api/missions/{id}/replay-export` returns the file, only with the preview's `digest`
  (400 without it, 409 if the mission changed since): the file is the content the director confirmed. The archive
  panel's "Export a replay…" button does both. Agents cannot call it: the API needs the session token agents never
  receive, Office's MCP server offers no such tool, and the shell guard refuses a command that names `replay-export`
  (a text check, like the token's: it stops plain attempts, it is no boundary). Nothing is journaled: exporting
  changes no state.
- **Cleaned by code, before anything is written** (`security/ReplaySanitizer`), on every text the file holds: the
  session token (replaced; and the file is refused if it would still hold it), the machine's known folders replaced
  by a named placeholder (`<repository>`, `<worktree:agent>`, `<office-data>`, `<home>`) in any spelling (either
  separator, doubled backslashes, Git Bash and WSL forms), any other local absolute path (`C:\...`, `\\server\...`,
  `/home/...`, `/Users/...`, `/mnt/...`, `/tmp/...`) replaced by `<path>`, then what looks like a secret masked by the
  same patterns as the stream parser: they now live in one class, `security/SecretMasker`, used by both. Tool and
  check outputs are clipped at 1500 characters, other texts at 2000. Never in the file: settings values (a
  `SettingChanged` line says a setting changed, without its value), the director's file contents (a workshop edit's
  diff), parameters and whole outputs. Fields are a whitelist: number, time, origin, actor, type, the event log's
  line, agent, ticket, tool, whether it ran, the clipped output, a cost.
- **Nothing added.** The file carries a header in an HTML comment and on the page: generated by Office version X,
  mission id, exported at, "events as recorded; nothing added". A cost appears only where the journal holds one (a
  session's end), labelled as Claude Code's estimate, as in the journal. At playback, a silence longer than 2 s
  between two events is shortened, and the file says so; the events and their order are the journal's.
- **Offline by construction.** The file's Content-Security-Policy is `default-src 'none'` with inline style and
  script only: it can load nothing and send nothing. The data is JSON in a script element, with `<`, `>` and `&`
  escaped; the player writes text with `textContent` only.
- **Its words.** The player's labels come from the screen's catalogue (`replayExport.file.*`, English and French),
  sent with the confirmation; the file plays in the language the director chose.
  Its event lines are English, written by the server from the screen's English catalogue (ADR-0021,
  amendment 2026-11-01).

## Consequences
- Over-masking is accepted: the secret patterns hide long hashes, UUIDs and long paths without spaces, so a line may
  read `Executed chris Read '[masked]'`. The preview shows every place masked; hiding too much is the safe side.
- A text check cannot know every secret: a short password in prose without a key name gets through. The preview is
  where the director catches it; the file is not sent anywhere by Office.
- The replay shows no 3D scene. If one is wanted later, it needs the API's answers recorded per event (as the online
  demo does), not this file.
